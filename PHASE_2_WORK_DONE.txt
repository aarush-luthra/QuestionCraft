QUESTIONCRAFT: PHASE 2 — PRODUCTIONIZATION & DEPLOYMENT
WORK SUMMARY (aligned with the "QuestionCraft Phase 2 Scope" document)
================================================================================
Institution : RV College of Engineering (RVCE), Bengaluru, India
Course      : AI254TA — Machine Learning Operations (MLOps), 5th Semester
Project     : QuestionCraft — Automated OBE Question Classification & Test Assembly

SCOPE
-----
In scope : model testing & data validation, model-risk quality gates, MLflow
           model registry, FastAPI inference service, blue-green & canary
           deployment, the 11 ML artifacts, Prometheus/Grafana observability,
           Docker + Compose, GitHub Actions CI/CD.
Out      : Kubernetes and statistical drift monitoring (removed from the repo).

The data checks are a custom rule-based implementation. Great Expectations and
Evidently AI are NOT used.

--------------------------------------------------------------------------------
1. MODEL TESTING & DATA VALIDATION
--------------------------------------------------------------------------------
- src/monitoring/model_tests.py: column existence, null ratio <= 1%, allowed
  label set, minimum length 5, row count 100-500,000, feature mean bounds,
  no duplicate rows; entry points validate_difficulty_dataset,
  validate_blooms_dataset, validate_inference_input.
- clean_text_dataset(): removes too-short texts, texts with conflicting labels
  and exact duplicates. On the processed difficulty data the raw check fails
  (22 short texts, 87,772 duplicate rows); after cleaning 191,775 -> 103,989
  rows and all 8 checks pass.
- src/data/build_splits.py (DVC stage build_splits): cleans BEFORE splitting,
  trains on public/proxy data, holds out real RVCE exam papers as a test set
  and removes any overlap so the held-out set never leaks.
- Tests: tests/test_model_quality.py, tests/test_models.py,
  tests/test_feature_engineering.py, tests/test_serving.py, tests/test_utils.py.

--------------------------------------------------------------------------------
2. MODEL-RISK & QUALITY GATES  (src/monitoring/quality_gates.py)
--------------------------------------------------------------------------------
  Minimum accuracy      >= 0.85
  Minimum F1-macro      >= 0.30
  No regression         <= 2.0% F1 drop vs current Production
  Stability             5-fold CV std <= 0.05
  Reproducibility       training data MD5 hash matches Production's
  Sample size           >= 100 test samples
- ModelRegistryManager.evaluate_promotion() runs all 6 gates on the real MLflow
  metrics of the Staging candidate vs the Production version.
- scripts/promote_model.py --to production refuses promotion if any gate
  fails (exit code 1, stages unchanged). TestPromotionIsRefused proves it.

--------------------------------------------------------------------------------
3. MODEL REGISTRY & PROMOTION  (src/registry/model_manager.py)
--------------------------------------------------------------------------------
- Lifecycle None -> Staging -> Production -> Archived (sqlite:///mlflow.db).
- Every version is tagged with data_hash, data_file, model_type, run_name and
  key metrics (set at training time; --sync-tags backfills older versions).
- CLI: --list, --to staging|production (gated), --compare A B, --rollback,
  --sync-tags.

--------------------------------------------------------------------------------
4. FASTAPI INFERENCE SERVICE  (src/serving/app.py, schemas.py, model_loader.py)
--------------------------------------------------------------------------------
  GET  /health, /docs, /redoc
  POST /predict, /classify, /batch/classify
  POST /dedup, /batch/dedup
  GET  /models/info     serving versions, canary version, ratio, registry stages
  POST /models/reload   re-reads the registry after a promotion or rollback
  GET  /artifacts       the 11-artifact manifest
  GET  /deploy/status, POST /deploy/canary
  GET  /metrics         Prometheus text exposition format

--------------------------------------------------------------------------------
5. DEPLOYMENT STRATEGIES (registry + API, no Kubernetes)
--------------------------------------------------------------------------------
- Blue-green: Production serves 100%; the Staging candidate is promoted only
  after the gates pass; POST /models/reload swaps it in; --rollback restores
  the previous version.
- Canary: ModelStore routes a configurable share (0.0-1.0) of requests to the
  Staging model; POST /deploy/canary?ratio=0.1 sets it.
- scripts/demo_for_evaluator.py drives the real API in-process and prints
  /models/info at baseline, canary 10%, after promotion and after rollback.

--------------------------------------------------------------------------------
6. THE 11 ML ARTIFACTS  (src/registry/artifacts.py)
--------------------------------------------------------------------------------
   1 Dataset                 data/processed/*.parquet (DVC) + data/splits/
   2 Preprocessing pipeline  src/data/preprocess.py, src/data/build_splits.py
   3 Trained models          models/*.pkl (difficulty, Bloom's, CT)
   4 Model configuration     configs/model_config.yaml
   5 Evaluation results      MLflow metrics (incl. rvce_* held-out metrics)
   6 Training logs           MLflow run telemetry
   7 Feature engineering     src/data/feature_engineering.py
   8 Tokenizer/vectorizer    TF-IDF saved inside each model pipeline
   9 Model metadata          MLflow registry version tags
  10 Deployment artifacts    Dockerfile, docker-compose.yml, CI workflow
  11 Monitoring artifacts    monitoring/prometheus.yml, Grafana dashboard +
                             provisioning
- GET /artifacts lists them; pipeline step 3 verifies every category.

--------------------------------------------------------------------------------
7. OBSERVABILITY
--------------------------------------------------------------------------------
- Metrics: questioncraft_requests_total, questioncraft_request_latency_
  seconds_total, questioncraft_predictions_total, questioncraft_models_loaded,
  questioncraft_uptime_seconds. Prometheus scrapes /metrics every 10 s;
  Grafana shows the provisioned dashboard on port 3000.

--------------------------------------------------------------------------------
8. DOCKER
--------------------------------------------------------------------------------
- Dockerfile: multi-stage (python:3.13-slim), dependencies pinned to the exact
  versions the models were trained with (requirements-serving.txt), CPU-only
  torch, single Uvicorn worker, HEALTHCHECK on /health.
- docker-compose.yml: API (8000), MLflow (5000), Prometheus (9090),
  Grafana (3000); host ports for MLflow/Grafana are overridable
  (MLFLOW_HOST_PORT, GRAFANA_HOST_PORT). The MLflow server is the single
  writer to the registry: the API uses http://mlflow-server:5000 and the host
  CLI uses MLFLOW_TRACKING_URI=http://localhost:<port> while the stack runs.
- Verified locally: all four services up, API healthy on registry v5 with
  v6 as canary, gated promote -> /models/reload -> rollback cycle, Prometheus
  scraping /metrics, all 5 Grafana panels returning data.

--------------------------------------------------------------------------------
9. CI/CD  (.github/workflows/ci.yml)
--------------------------------------------------------------------------------
  1 Ruff + Black (strict)
  2 PyTest with coverage on Python 3.10 and 3.11
  3 Phase 2 pipeline (CI seeds demo artifacts; registry-dependent checks can
    only pass where the trained registry exists, so this step is non-strict)
  4 Docker image build
  5 Smoke test: start the container, /health must return 200 with all models
    loaded, /predict and /metrics must answer
  6 Push to a container registry: open question, not implemented

--------------------------------------------------------------------------------
10. HONEST EVALUATION NOTES
--------------------------------------------------------------------------------
- The earlier 0.97 accuracy / 0.95 F1 for the difficulty model came from
  duplicates leaking between train and test. After de-duplication: LR 0.92 /
  0.66, XGBoost 0.95 / 0.69 (in-domain).
- On real RVCE papers (held out, never trained on) the models do not yet beat
  a majority-class baseline (difficulty 0.46 vs 0.46, Bloom's 0.24 vs 0.47).
  RVCE difficulty/CT labels are LLM drafts pending faculty review, so these
  numbers are reported, not gated.
