2.1. Model Testing & Data Validation Suite (Great Expectations-Style)
--------------------------------------------------------------------
- Implementation: src/monitoring/model_tests.py
- Unit Tests    : tests/test_model_quality.py (24 tests)
- Capabilities:
    * Column existence validation (expect_column_to_exist)
    * Null-ratio upper-bound enforcement (expect_column_values_not_null, max 1%)
    * Valid categorical set constraints (expect_column_values_in_set: Easy/Med/Hard)
    * Minimum character length bounds (expect_column_min_length >= 5 chars)
    * Table row count range limits (expect_table_row_count_between 100-500,000)
    * Feature distribution mean bounds (expect_column_mean_between)
    * Uniqueness verification (expect_no_duplicate_rows)
    * Complete dataset validation pipelines: validate_difficulty_dataset,
      validate_blooms_dataset, and validate_inference_input.

2.2. Model Risk & Quality Gate Checks (Unit III Governance)
----------------------------------------------------------
- Implementation: src/monitoring/quality_gates.py
- Capabilities:
    * Automated pre-promotion validation blocking inferior models from production:
        1. Minimum Accuracy Gate: Accuracy >= 0.85
        2. Minimum F1-Macro Gate: F1-macro >= 0.30
        3. No-Regression Gate   : Max allowed performance drop vs. production <= 2.0%
        4. Stability Gate       : 5-Fold Cross-Validation standard deviation <= 0.05
        5. Reproducibility Gate : MD5 data hash matching expected hash
        6. Sample Size Gate     : Test sample count >= 100
    * Orchestrated via run_full_quality_check() returning detailed gate verdicts.

2.3. Statistical Data & Prediction Drift Monitoring (Evidently AI-Style)
------------------------------------------------------------------------
- Implementation: src/monitoring/drift_detection.py
- Reports Directory: reports/drift/drift_report.json
- Capabilities:
    * Continuous Numerical Feature Drift: Two-sample Kolmogorov-Smirnov (KS) test
      measuring p-value and KS-statistic across word length, reading ease, etc.
    * Categorical Label Drift: Chi-squared (chi2) contingency test detecting
      distribution divergence between reference training and live inferences.
    * Data Quality Profiling: Missing values, empty strings, duplicate detection.
    * PredictionDriftMonitor: In-memory tracker logging live predictions and
      alerting if class distribution deviates by > 15%.

2.4. Model Registry & Promotion Lifecycle (MLflow Model Registry)
-----------------------------------------------------------------
- Implementation: src/registry/model_manager.py
- Promotion CLI : scripts/promote_model.py
- Tracking Store: sqlite:///mlflow.db
- Capabilities:
    * Versioned model lifecycle: None -> Staging -> Production -> Archived
    * Quality-gated promotion: Staging models must satisfy all quality gates
      before being promoted to active Production.
    * Version comparison: scripts/promote_model.py --compare v1 v2 compares metrics
      and highlights winning models automatically.

2.5. Deployment Strategies: Blue-Green & Canary (Unit IV)
---------------------------------------------------------
- Implementation: src/serving/model_loader.py & k8s/deployment.yaml
- Deployment Strategies:
    1. Blue-Green Zero-Downtime Deployment:
       * Production (Blue) serves 100% of traffic. Staging (Green) is deployed
         and verified in isolation.
       * Promotion swaps stages in MLflow and Kubernetes with zero request drops.
       * Instant Disaster Recovery: scripts/promote_model.py --model difficulty --rollback
         restores the previous production model in < 100ms.
    2. Canary Deployment:
       * Configurable traffic splitting (0.0 to 1.0) via POST /deploy/canary?ratio=0.1.
       * ModelStore routes a defined percentage (e.g., 10%) of live production
         requests to candidate model in staging while 90% stays on baseline.
       * Kubernetes Canary Track: Dedicated 1-replica canary deployment runs alongside
         3 stable production replicas under a shared service selector.

    * GET  /metrics        : Prometheus-compatible text metrics export

--------------------------------------------------

- docker-compose.yml: 4-service coordinated development & evaluation stack:
    * questioncraft-api  (FastAPI on port 8000)
    * questioncraft-mlflow (MLflow UI on port 5000)
    * questioncraft-prometheus (Metrics scraper on port 9090)
    * questioncraft-grafana (Dashboards on port 3000)
- .dockerignore     : Excludes caches, DVC data, reports, and dev artifacts.

2.9. Kubernetes Cloud-Native Orchestration (k8s Manifests)
----------------------------------------------------------
- Directory: k8s/
- Manifests Implemented:
    * k8s/namespace.yaml : Isolated "questioncraft" namespace
    * k8s/configmap.yaml : Externalized environment variables (logging, URIs, canary)
    * k8s/deployment.yaml: RollingUpdate deployment (maxSurge=1, maxUnavailable=0),
      liveness/readiness/startup probes, CPU/RAM limits, and Canary track.
    * k8s/service.yaml   : NodePort service routing external traffic on port 30800.
    * k8s/hpa.yaml       : HorizontalPodAutoscaler scaling from 2 to 10 replicas
      based on 70% CPU and 80% RAM thresholds.
    * k8s/ingress.yaml   : NGINX Ingress rules routing /docs, /metrics, and /.

5. EVALUATION DEMO GUIDE & COMMAND CHEAT SHEET

Command 1: Terminal Walkthrough Demo (1-command execution)
---------------------------------------------------------
$ python scripts/demo_for_evaluator.py
(Runs data validation, quality gates, live predictions, 11 artifacts table,
canary routing simulation, and statistical drift checks with clear visual output.)

Command 2: Start the Live Production API Server
-----------------------------------------------
$ python -m uvicorn src.serving.app:app --host 0.0.0.0 --port 8000
Then open in browser:
- Swagger Interactive Documentation : http://localhost:8000/docs
- ReDoc Alternative Documentation  : http://localhost:8000/redoc
- 11 ML Artifacts Manifest         : http://localhost:8000/artifacts
- Prometheus Metrics Export        : http://localhost:8000/metrics

Command 3: Model Registry Promotion CLI (Blue-Green Swap & Rollback)
--------------------------------------------------------------------
$ python scripts/promote_model.py --list
$ python scripts/promote_model.py --model difficulty --to staging
$ python scripts/promote_model.py --model difficulty --to production
$ python scripts/promote_model.py --model difficulty --rollback

Command 4: Docker Compose Full Stack Launch
-------------------------------------------
$ docker compose up -d
(Spins up FastAPI on :8000, MLflow UI on :5000, Prometheus on :9090, Grafana on :3000)
